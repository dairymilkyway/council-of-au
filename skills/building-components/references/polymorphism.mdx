The `as` prop allows you to change the underlying HTML element or component that gets rendered.

## Implementation

```tsx
type PolymorphicProps<E extends React.ElementType> = {
  as?: E;
} & React.ComponentPropsWithoutRef<E>;

function Component<E extends React.ElementType = "div">({
  as, ...props
}: PolymorphicProps<E>) {
  const Element = as || "div";
  return <Element {...props} />;
}
```

## `as` vs `asChild`

| Feature | `as` prop | `asChild` + Slot |
|---|---|---|
| API Style | `<Button as="a">` | `<Button asChild><a /></Button>` |
| Component Composition | Limited | Full support |
| Prop Merging | Basic spread | Intelligent merging |
| Ref Forwarding | Manual setup | Built-in |

**Use `as`** for simple element switching. **Use `asChild`** for complex composition with other components.

## TypeScript Best Practices

```tsx
// Props are inferred from the element type
<Component as="a" href="/home">Home</Component>  // href valid
<Component as="div" href="/home">Home</Component> // TS error
```

## Common Pitfalls

- Watch for invalid HTML nesting (button inside button, div inside p)
- Add proper ARIA attributes when using non-semantic elements
- Keep component references stable to avoid re-render issues
